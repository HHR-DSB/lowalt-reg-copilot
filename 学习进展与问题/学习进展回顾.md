## 六、历史遗留注意事项

- LLM 统一用 `qwen3.8-27b`；服务虽开 `--reload`，但有 volumes 目录坑（见下方专条）——**改代码后重启服务才最稳**
- Docker 与代理共存：系统代理模式无碍；**TUN 模式与 Docker 同时开可能断网**，遇异常先退一方
- Milvus 容器健康检查有 90 秒预热，`(health: starting)` 属正常
- `docker compose down` 保留数据卷，`down -v` 连数据一起删（一字之差，天壤之别）
- Windows 代理开启时 WSL 弹"Http 代理更改"提示可无视，本地 Milvus 不走代理
- rag_service.py 第 407 行旁路条件已改为 `>= 0.5`（原逻辑反转，详见问题记录第六节）
- **曲线化 PDF（文字转矢量轮廓的防拷贝件）检测三步法**：`get_text()` 字符数为 0 → `get_drawings()` 每页数百上千对象 → 渲染成图肉眼确认；应对路径优先级：官方 HTML 源 > 多模态 OCR（qwen3.5-ocr，注意其输出为 HTML 格式需清洗）
- **OCR/模型额度坑**：qwen-vl-ocr 免费额度已耗尽（403 AllocationQuota.FreeTierOnly）→ 换 qwen3.5-ocr（有免费额度）；换模型不只是换名字，**输出契约也变**（纯文本 → HTML）
- **清洗原则两条**：孤例修数据、规律进规则；页眉清洗必须整行相等，前缀匹配会误杀"民用无人驾驶航空器"这类高频行首主语
- **⚠ uvicorn reload + MinIO 数据卷 = reloader 无声死亡（10-26 最隐蔽的坑）**：StatReload 扫描项目目录时扫进 `volumes/`（MinIO 卷，海量小文件 + Milvus 写入时动态增删），扫到"中途消失的路径"直接 FileNotFoundError 崩掉 reloader 主进程——worker 变孤儿继续服务旧代码，**症状：服务活着、请求正常、日志照打，唯独改代码永远不生效**（本次 Rerank 验证假失败就是它）。修复：两个服务的 `uvicorn.run` 加 `reload_excludes=["volumes*", "ocr_cache*", "milvus.doc*", "*.log"]`。教训：开发目录与数据目录必须分离；"服务正常响应"≠"跑的是新代码"，改完代码重启最稳
- **DashScope rerank 不是 OpenAI 兼容格式**：独立端点 `/api/v1/services/rerank/text-rerank/text-rerank` + Bearer 认证，input={query, documents}，返回 output.results[{index, relevance_score}]；模型 `qwen3.7-text-rerank` 有免费额度（qwen-vl-ocr 已耗尽，命名同系的额度状态不同，换模型前先探测）
