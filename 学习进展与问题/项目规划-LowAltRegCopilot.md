# LowAlt-Reg Copilot：我自己的 RAG 项目规划

> 制定时间：2026-10-25
> 目标：面向 **Agent 应用开发实习**，把 RAG 学习项目转化为有差异化竞争力的个人项目
> 命名：低空空域规章智能问答助手（LowAlt-Reg Copilot）

---

## 一、选题依据（基于简历三张领域牌）

| 领域资产 | 来源 | RAG 契合度 | 稀缺度 |
|---|---|---|---|
| UAV-MEC 科研（NOMA/MADDPG，两篇学生一作） | 论文 | 中：文献问答需求真实但同质化严重 | 低 |
| **低空空域规章 + 川渝协同运行平台实习** | 四川省低空空域运行服务中心（2026.04-06） | **高：规章权威、需引用、频繁更新、术语密集** | **极高** |
| 民航院校背景（中国民航飞行学院 7 年） | 教育 | 叙事可信度加持 | 中 |

**决策：旗舰项目做"低空规章问答"，科研文献降级为第二集合（个人科研用）。**

核心理由：
1. **稀缺性**：投 Agent 实习的人 90% 做"论文助手"，几乎无人做"低空规章问答"；而低空经济是 2025-2026 国家级政策风口
2. **一线视角**：实习中"系统研读低空规章、参与平台运行保障"——知道一线人员每天翻规章的痛点，面试叙事："我在实习中看到问题 → 我用技术解决了它"
3. **与学习项目同构**：law.md 就是微型法规 RAG 预演，现在换成真法规、真用户、真评估
4. **工程零浪费**：两个集合共享全部解析/切块/检索管线；双栏英文论文解析技能照样练

## 二、项目路线图（四阶段）

```
阶段0 机制练习(本周) → 阶段1 规章语料+MVP → 阶段2 工程深化 → 阶段3 Agent化 → 阶段4 展示打磨
```

### 阶段 0 · 机制练习（当前，进行中）

- 内容：PDF 解析（pymupdf）+ 滑动窗口重叠切块 + 沙箱集合 `pdf_practice` 入库验证
- 素材：milvus.doc 下 3 个中文报告 PDF（150 页）
- 注意：这 3 个 PDF 与 3 个 md 是同一批报告，**必须入沙箱集合，不能污染 ai_knowledge_base**
- 完成标志：pdf_insert.py 跑通，检索验证切片质量

### 阶段 1 · 规章语料 + MVP

| 文档 | 性质 | 获取渠道 |
|---|---|---|
| 《无人驾驶航空器飞行管理暂行条例》 | 国务院/中央军委，2024 施行 | 中国政府网公开 |
| CCAR-92 部《民用无人驾驶航空器运行安全管理规则》 | 民航局规章 | 民航局官网 |
| 四川省低空空域协同管理相关公开文件 | 地方试点特色 | 公开渠道整理 |
| 实习期间自己写的规章学习笔记/流程总结 | 独家语料 | 自己手里 |

- 建正式集合（如 `lowalt_reg_kb`），复用阶段 0 的解析入库管线
- MVP：FastAPI 服务，带引用问答（参考 rag_service.py 的引用标注 + 诚实条款 Prompt）
- **保密红线：实习接触的内部文件、平台数据一律不入库——只用公开规章 + 自己撰写的笔记**（数据合规意识本身是面试加分项）

### 阶段 2 · 工程深化

| 能力 | 选型 | 面试考点 |
|---|---|---|
| Rerank 重排 | 阿里云百炼 gte-rerank（现有 DASHSCOPE_KEY 直接用） | 为什么向量召回后还要重排（召回 vs 精排两阶段） |
| 评估体系 | RAGAS 四指标：Faithfulness / Answer Relevancy / Context Precision / Recall | **杀手锏——绝大多数学生项目没有评估** |
| 流式输出 | SSE（参考 rag_service.py 的 /chat/stream） | 用户体验与首 token 延迟 |
| 多轮会话 | 会话管理（参考 /chat/with-history） | 上下文工程 |

### 阶段 3 · Agent 化（实习敲门砖）

把问答升级为工具编排的 Agent：

- **工具 1**：`search_regulation(query)` —— 规章检索（RAG 本体）
- **工具 2**：`check_airspace_rules(...)` —— 规则查询（管制空域/适飞空域判断）
- **工具 3**：`calc_*` —— 计算（如高度层换算）
- 技术路径：qwen Function Calling → ReAct 循环 → 封装为 **MCP Server**（Agent 生态通用协议，简历关键词）

### 阶段 4 · 展示打磨

- GitHub：README 含架构图 + 评估数据 + 使用截图
- docker compose 一键部署（前端简版页面可选）
- 面试话术打磨：每个技术决策都有"为什么"
